SECTION 1: SYSTEM ARCHITECTURE & OVERVIEW
====================================================================================================

OpenClaw is an Enterprise Multi-Tenant AI Agent Orchestration and Retrieval-Augmented Generation (RAG) platform built in Python. 

Core Architecture:
- Frontend UI: Streamlit high-contrast glassmorphic single-page web app with real-time audio microphone recording, chat thread management, document uploads, agent lifecycle controls, and team workspace administration.
- REST API Backend: FastAPI async server serving endpoints for Auth (JWT + Refresh Tokens), Team Workspaces, Agent Lifecycle Management, Document Ingestion, Context Brief Compiling, Voice Transcription, WebSocket streaming, and Governance Audit Logging.
- Database: PostgreSQL 16 with the pgvector extension for unified multi-tenant relational persistence and 384-dimensional vector embedding store.
- Task Queue & Background Workers: Celery distributed task queue backed by Redis for asynchronous long-running background tasks (Docker agent container spin-up/teardown, document chunking & vector embedding generation, LLM query grounding, and periodic idle container pruning).
- Real-Time Pub/Sub: Redis Pub/Sub for broadcasting container status events and chat message execution feedback over WebSockets.
- Container Security Sandboxing: Docker Python SDK orchestrating isolated Docker containers (`alpine:latest`) per active agent with read-only root filesystems, dropped Linux capabilities (`CAP_DROP=["ALL"]`), disabled networking (`network_mode="none"`), memory limits (256MB), CPU limits (0.5 CPU), and local workspace volume binds (`/workspace/MEMORY.md`).
- LLM Provider Interface: Groq API integration using `llama-3.3-70b-versatile` (or optional local TGI Text Generation Inference endpoint) for high-speed inference.
- Local RAG Embeddings Engine: `SentenceTransformers` (`all-MiniLM-L6-v2`) generating 384-dimensional dense vectors stored in pgvector.
- Voice STT Integration: Groq Audio Transcriptions API powered by `distil-whisper-large-v3-en` (with fallback to `whisper-large-v3`) with automated hallucination filtering.

SECTION 3: ARCHITECTURAL DESIGN & ALTERNATIVE COMPARISON ("WHY THIS AND NOT SOMETHING ELSE")
====================================================================================================

1. Why FastAPI instead of Flask or Django?
   - Asynchronous I/O Native Support: FastAPI relies on `asyncio`, enabling non-blocking execution for WebSocket connections, database queries, and external HTTP calls. Flask is traditionally synchronous and handles concurrent requests poorly without gevent/gunicorn wrappers.
   - Pydantic Integration: Automatic data validation, serialization, and error responses without manual boilerplate.
   - Speed: Benchmark tests place FastAPI alongside Node.js and Go in performance, far outperforming Django.

2. Why Streamlit instead of React / Next.js?
   - Development Speed & Pure Python Ecosystem: Streamlit enables building rich, stateful web interfaces entirely in Python without requiring a separate Node.js build system, frontend packages, or TypeScript compilation.
   - Direct Session State: Simplifies state management (tokens, active agent selection, thread history) across tab reruns.

3. Why PostgreSQL + pgvector instead of a dedicated Vector DB (Pinecone, ChromaDB, Weaviate)?
   - Single Database Architecture (ACID Compliance): Eliminates data synchronization drift between relational data (teams, documents, agent ownership) and vector data. Deleting a document in PostgreSQL automatically cascades and deletes its vectors via standard SQL `ON DELETE CASCADE`.
   - Zero Additional SaaS Cost / Self-Hosted Simplicity: Running `pgvector` inside the PostgreSQL container costs $0 and requires no external API keys or cloud service subscriptions.

4. Why Celery + Redis instead of Python BackgroundTasks / ThreadPoolExecutor?
   - Process Isolation & Reliability: FastAPI's built-in `BackgroundTasks` run inside the ASGI web process. If a heavy document extraction or LLM call crashes or leaks memory, it crashes the web server. Celery runs in isolated worker processes that can be scaled horizontally.
   - Distributed Task Persistence: Tasks queued in Redis survive server restarts and can be retried automatically.

5. Why Docker SDK Sandboxing instead of raw `subprocess` or `exec` execution?
   - Security & System Protection: Running untrusted AI agent code or file outputs via raw `subprocess` allows malicious or faulty scripts to access the host OS filesystem, network, and environment secrets. Docker containers enforce strict isolation with `read_only` root filesystems, dropped capabilities (`CAP_DROP=["ALL"]`), disabled network access (`network_mode="none"`), and hard memory/CPU caps.

6. Why SentenceTransformers `all-MiniLM-L6-v2` instead of OpenAI `text-embedding-3-small`?
   - Local, Offline & Zero API Cost: SentenceTransformers runs locally inside the application container, generating embeddings instantly without external API rate limits, billing, or network latency.
   - High Performance: 384 dimensions provide high semantic accuracy for domain documents while occupying minimal memory and storage space in pgvector.

7. Why Groq API (`llama-3.3-70b-versatile`) instead of standard OpenAI GPT-4?
   - Extreme Inference Speed (LPU Hardware): Groq's Language Processing Units (LPUs) deliver speeds of 300+ tokens per second, making agent interactions feel instant.
   - Cost-Efficiency: Significantly lower cost per million tokens compared to GPT-4o.
