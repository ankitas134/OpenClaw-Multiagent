1. SYSTEM OVERVIEW & ARCHITECTURE PURPOSE
--------------------------------------------------------------------------------
The OpenClaw Platform is a high-performance, multi-tenant enterprise AI Agent 
orchestration system. It allows organizations to deploy isolated AI Agents 
operating inside secure, resource-capped Docker containers. 

Key Platform Capabilities:
1. Multi-Tenant Team Workspaces: Role-Based Access Control (RBAC) supporting 
   Owners, Admins, and Members.
2. Strict Security Sandboxing: Every agent runs in a dedicated Docker sandbox 
   with 256MB RAM caps, 0.5 CPU limits, read-only root filesystems, and zero 
   external network access.
3. Strict Per-Agent Document RAG: Vector search (PostgreSQL pgvector) queries 
   only reference documents explicitly attached to that specific agent ID.
4. Multimodal Input: Text chat and native browser speech-to-text live microphone 
   input powered by Groq Whisper.
5. High-Speed LLM Inference: Powered by Groq Llama-3.3 70B Engine.
6. Persistent ChatGPT-Style UI: Multi-thread sidebar navigation, instant 
   thread deletion, context brief compilers, and audit logging.

--------------------------------------------------------------------------------
2. TECHNICAL STACK & INFRASTRUCTURE
--------------------------------------------------------------------------------
- Frontend: Streamlit >= 1.40 (Python) with custom Dark Glassmorphism CSS, 
  Plus Jakarta Sans typography, and native browser microphone recorder (`st.audio_input`).
- Backend API: FastAPI (Python 3.11), SQLAlchemy AsyncSession, Pydantic v2.
- Database: PostgreSQL 15+ with `pgvector` extension for 384-dimensional vector embeddings.
- Async Broker & Workers: Redis 7.0 & Celery 5.3 background task queue for 
  asynchronous container spin-up, document embedding chunking, and LLM processing.
- Container Infrastructure: Docker Engine SDK (`docker` Python package).
- AI Models & APIs:
  * Text LLM Inference: Groq API (`llama-3.3-70b-versatile`)
  * Speech STT Transcription: Groq API (`distil-whisper-large-v3-en`, English enforced)
  * Vector Embeddings: SentenceTransformers / Nomic-embed-text (384-dim)

4. STEP-BY-STEP DATA FLOW & WORKFLOW EXPLANATION
--------------------------------------------------------------------------------

[WORKFLOW 1: TEXT QUERY & RAG PROCESSING]
1. User types a question (e.g., "What is the net profit?") in Streamlit UI and hits Enter.
2. Streamlit calls `POST /api/agents/{agent_id}/messages` with payload `{"text": "...", "threadId": "..."}`.
3. FastAPI saves user message to `agent_messages` table and dispatches `process_message_task.delay()` to Celery/Redis.
4. Celery worker receives job:
   a. Generates 384-dim embedding for user prompt.
   b. Queries PostgreSQL `document_chunks` table joining `agent_documents` where `agent_id` matches strictly.
   c. Ranks matching chunks by cosine similarity score (> 0.15 threshold).
   d. Assembles context string from top 5 document chunks + agent `MEMORY.md` brief + standing team guidelines + thread message history.
   e. Calls Groq Llama-3.3 LLM engine.
5. Celery worker saves AI assistant response to `agent_messages` and updates status to completed.
6. Streamlit UI fetches updated messages and displays response bubble in chat view.

[WORKFLOW 2: LIVE VOICE RECORDING & TRANSCRIPTION]
1. User clicks the live microphone button under "Live Microphone Speech Input".
2. Browser records microphone audio in WAV format.
3. User clicks "Transcribe Voice & Send to Agent".
4. Streamlit sends WAV bytes to `POST /api/voice/transcribe`.
5. FastAPI `voice.py` receives file, sets `language="en"`, and calls Groq Whisper (`distil-whisper-large-v3-en`).
6. Groq Whisper transcribes speech into English text string.
7. Streamlit automatically submits transcribed text string to Workflow 1 (Text Query Flow).

[WORKFLOW 3: TEAM WORKSPACE SHARING & ISOLATION]
1. User A creates an agent named "Finance Assistant". By default, visibility is set to `personal` (Private to User A).
2. User A clicks "Share Agent with Team" button in Agent Hub.
3. Backend updates `visibility = 'team'` in PostgreSQL `agents` table.
4. User A invites User B via email in "Team Guidelines" tab (`POST /api/teams/{team_id}/members`).
5. User B logs in. The sidebar dropdown lists User A's team workspace (`A's Team (MEMBER)`).
6. User B selects the shared team workspace. The "Finance Assistant" agent appears for User B to chat with, while maintaining complete container sandbox isolation.

5. SECURITY GUARANTEES & COMPLIANCE SUMMARY
--------------------------------------------------------------------------------
1. Client Sandbox Override Prevention: Sandbox parameters are server-enforced constants (`SERVER_SANDBOX_SETTINGS`). Client API payloads attempting to send custom sandbox keys are rejected with HTTP 422.
2. No Silent Unsandboxed Fallback: If Docker daemon is unavailable, container spinup fails explicitly with `RuntimeError` and status `failed`. The platform NEVER executes agent code on the host machine.
3. Strict Document RAG Isolation: Vector search queries only search document chunks linked to the active `agent_id` via `agent_documents` table.
4. Multilingual Noise Hallucination Fix: Voice transcription enforces `distil-whisper-large-v3-en` with `language="en"` context to eliminate non-English noise hallucinations.
